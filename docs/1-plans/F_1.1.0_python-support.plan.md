# Plan: F_1.1.0 — Python language support

**Goal**: `spokes check` / `graph` / `suggest` / `explain` work on Python projects (and mixed
TS+Python repos) with the same four rules (R1–R4), the same diagnostics contract, and the same
deterministic output guarantees. No new runtime dependencies; no Python interpreter required —
imports are parsed with a hand-rolled scanner, mirroring how the TS side avoids a full
type-checker.

## Language mapping

| Concept | TS/JS (existing) | Python (new) |
|---|---|---|
| Import edge | `import`/`export from`/`require`/dynamic `import()` | `import a.b`, `from x import y`, relative `from . import y` |
| Type-only edge | `import type { T }` | imports inside an `if TYPE_CHECKING:` block |
| Export count (R4) | value-export names | `__all__` entries if present, else public top-level `def`/`class` names |
| Role pragma | `// @spokes hub` | `# @spokes hub` |
| External package | node_modules / bare specifier | unresolvable absolute import (stdlib / site-packages) |
| Repo root marker | `package.json` | `pyproject.toml` (or `spokes.config.json` itself) |

## Modules

1. **`src/core/parser-py.ts`** — single export `parsePythonFile(absPath)`, returning the same
   `{ specifiers, exports }` shape as `parser.ts`, with one extra optional per-specifier field
   `fromImport?: boolean` (drives the resolver's submodule-vs-name fallback). Implementation:
   - Mask string literals (incl. triple-quoted / f-strings) and `#` comments character-by-character,
     preserving line/col positions — prevents false imports inside docstrings.
   - Join logical lines (trailing `\` and open-paren continuation) so
     `from x import (a,\n b)` parses as one statement.
   - `if TYPE_CHECKING:` blocks tracked by indentation; imports inside are `typeOnly`.
   - Specifier text is the dotted form: `pkg.mod`, `.sibling`, `..pkg.name`. `from X import a, b`
     emits one specifier per name (`X.a`, `X.b`) with `fromImport: true`.
   - Exports: a top-level `__all__ = [...]` literal wins; otherwise column-0
     `def`/`async def`/`class` names not starting with `_`, deduplicated.
2. **`src/core/resolver-py.ts`** — single export
   `resolvePythonSpecifier(repoRoot, fromAbsPath, text, fromImport)`, same `ResolveResult` shape:
   - Leading dots → relative base (`.` = same package, each extra dot = one level up).
   - Candidate file forms: `<path>.py`, then `<path>/__init__.py`.
   - `fromImport` fallback: try `X.name` as a module first, then `X` (matches Python semantics —
     `from pkg import mod` vs `from pkg import symbol`).
   - Absolute imports search `repoRoot` then `repoRoot/src`; not found → `bare` (external).
     Relative not found → `unresolved` (E-RESOLVE), same as TS.
3. **`src/graph-builder.ts`** — dispatch per file on the `.py` extension to the Python
   parser/resolver pair; everything downstream (rules, renders, commands) is graph-level and
   unchanged. Architectural note: graph-builder is a hub (out-degree unconstrained), so the two
   new value imports are legal; both new core modules are spokes with zero value imports
   (types-only) and exactly one export each.
4. **Small edits**:
   - `roles.ts`: pragma regex accepts `#` comments.
   - `config.ts` + `init.ts`: default include glob gains `py`; `findRepoRoot` accepts
     `spokes.config.json`, `package.json`, or `pyproject.toml` as a root marker.
   - `r3-acyclicity.ts` + `suggest.ts` (`reconstructSpecifier`, deliberately duplicated per the
     v1.0.0 plan): emit Python dotted relative form (`.mod`, `..pkg.mod`) when the target is `.py`;
     `__init__.py` collapses to its package.
   - `suggest.ts` + `render/diff.ts`: all-Python cycles propose `shared_hub.py` with
     `# @spokes hub` pragma and Python-style stub/import lines. Mixed-language cycles are
     impossible (no cross-language imports), so per-cycle language detection is total.
   - `schema.json`: unchanged — no new config fields.
5. **Fixture `f11-python`** — pure-Python repo rooted by `pyproject.toml` (no `package.json`),
   exercising: S001 (spoke fan-out), S002 (`#`-pragma hub imported twice), S003 (2-cycle mixing
   relative and absolute imports), S004 (multi public defs) alongside `__all__` suppressing it,
   from-import submodule fallback, `from . import x`, TYPE_CHECKING edge ignored (would otherwise
   close a second cycle), bare `import os` ignored. `expected.json` + `expected-suggest.txt`
   generated from real CLI runs and hand-verified.
6. **`tests/python.test.ts`** — unit tests for the parser (import forms, docstring masking,
   `__all__`, TYPE_CHECKING) and resolver (relative/absolute/fallback/bare); the existing fixture
   loop picks up f11 automatically.
7. **README** — Python usage section: config example, pragma syntax, what counts as an export,
   known limitations (no namespace-package name resolution, `__all__` mutations ignored,
   no `sys.path` customization).

## Out of scope (documented as limitations)

- `importlib.import_module(...)` / `__import__` dynamic imports.
- Editable-install path mappings, `sys.path` hacks, namespace-package cross-package resolution.
- `suggest --write` (still reserved, both languages).
