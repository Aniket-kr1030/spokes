## Changes

All four rules, all four commands, and the diagram now work on Python projects (and mixed
TS+Python repos). No new runtime dependencies and no Python interpreter — imports are parsed by
a hand-rolled scanner, mirroring how the TS side skips the type-checker.

- **`src/core/parser-py.ts`** (new): masks string literals and `#` comments so docstrings can't
  produce false imports; joins parenthesized/backslash-continued statements into logical lines;
  handles `import a.b [as x]`, `from x import (a, b)`, relative `from . import y`, and
  `from m import *`; imports inside `if TYPE_CHECKING:` blocks are type-only (the `import type`
  analog, governed by the existing `typeOnlyEdges` setting); R4's export count comes from a
  literal `__all__ = [...]` when present, else public top-level `def`/`class` names.
- **`src/core/resolver-py.ts`** (new): filesystem-only resolution of dotted specifiers to
  `mod.py` / `pkg/__init__.py`; `from pkg import thing` tries the submodule reading first and
  falls back to the package, matching Python's import machinery; absolute imports search
  repoRoot and repoRoot/src; not found → external (like a bare specifier), relative miss →
  E-RESOLVE.
- **`src/graph-builder.ts`**: per-file extension dispatch to the right parser/resolver pair —
  everything downstream of the graph stays language-agnostic.
- **`src/core/roles.ts`**: `# @spokes hub|spoke` pragma accepted.
- **`src/core/config.ts`**: `pyproject.toml` (or `spokes.config.json` itself) accepted as a
  repo-root marker; default include glob gains `py`. Same default change in `src/init.ts`.
- **`src/rules/r1-spoke-outdegree.ts`**: the help line spells the pragma in the flagged file's
  own comment syntax (`# @spokes hub` for `.py`). TS/JS messages are byte-identical to before.
- **`src/rules/r3-acyclicity.ts` + `src/suggest.ts` + `src/render/diff.ts`**: Python cycles get
  Python-style output — dotted relative specifiers (`.mod`, `..pkg.mod`), a `shared_hub.py`
  proposal with `# @spokes hub` pragma and `from .TODO import name` stub lines.
- **Fixture `f11-python`** (new): pure-Python mini-repo rooted by `pyproject.toml` (no
  `package.json`), exercising S001–S004, the `#` pragma, `__all__`, TYPE_CHECKING, the
  from-import fallback, and a Python-style suggest preview (`expected.json` +
  `expected-suggest.txt` captured from real CLI runs).
- **`tests/python.test.ts`** (new): 13 unit tests for the parser and resolver; the fixture
  suggest comparison in `tests/fixtures.test.ts` generalized to any fixture with an
  `expected-suggest.txt`.
- **README**: new "Python support" section (concept mapping, config example, resolution details,
  known limitations); language claims, pragma docs, roadmap, and `docs/ARCHI.md` module map
  updated.

Known limitations (documented in the README): dynamic imports
(`importlib.import_module`/`__import__`) are invisible; `__all__` built by mutation is ignored;
namespace packages without `__init__.py` can't anchor `from . import name` fallbacks; `sys.path`
customization is not consulted.

47 tests pass (32 existing unchanged + 15 new); the tool still passes `spokes check` on itself.
