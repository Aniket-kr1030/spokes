# Changelog - Week 1, 21-07-2026, V. 1.1.2

**Release Date**: Week 1, 21-07-2026
**Version**: 1.1.2 (previously 1.1.1)
**Object**: Close coverage gaps (explain/init/graph-split) and sanitize split-diagram filenames
**Code review**: `docs/3-code-review/CR_w1_v1.1.2.md`

## Changes

Follow-up to a completeness audit of the project. No stubs were found — every module has exactly
one implemented export and all five commands work — but the audit surfaced two real gaps, both
fixed here.

### Fix: split-diagram filenames carried path punctuation

`src/graph.ts` builds output filenames for the >300-node split path with the same stale
`replace(/[/.]/g, '_')` that caused the v1.1.1 Mermaid-id bug. A top-level group like
`src/(app)` (a Next.js route group) produced `spokes-graph-src_(app).html`. Not a crash — parens
are legal in filenames — but inconsistent with the renderers and awkward to reference from
scripts. Now uses the same word-only sanitization as `render/mermaid.ts`'s `nodeId()`.

### Coverage: `explain` and `init` had no tests at all

Both were implemented and working but entirely unguarded against regression — notable for `init`,
which writes a config file into *other people's* repos and whose `$schema` value already broke
once (v1.0.4's package rename). New `tests/commands.test.ts` (8 tests):

- `explain`: reports role/exports/both edge directions/per-rule status; surfaces the correct rule
  as FAIL for a genuinely violating file; normalizes `./src/x.ts` and `src/x.ts` to the same
  output; exits 2 with a clear message for a path not in the graph.
- `init`: writes valid, newline-terminated JSON that `check` can immediately load; `$schema`
  points at the **current** `package.json` name (so a future rename can't silently break it
  again); default include glob covers both TS/JS and Python; refuses to overwrite an existing
  config (exit 2, original bytes untouched).

### Coverage: the >300-node graph split path had no tests

New `tests/render/graph-split.test.ts` generates a 320-file repo (too large to commit as a
fixture) spanning a plain group and a `src/(app)` route group, and asserts the split message, the
per-group + overview diagrams, and punctuation-free filenames. Verified to be a genuine
regression guard: reverting the `graph.ts` fix makes it fail with
`expected 'spokes-graph-src_(app).html' to match /^[A-Za-z0-9_.-]+$/`.

60 tests pass (was 51: +8 command tests, +1 split test). `spokes check` on itself stays clean.
