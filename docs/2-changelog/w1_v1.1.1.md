## Changes

`spokes graph` produced a completely broken diagram on any repo whose file paths contain `(`,
`)`, `[`, or `]` — most commonly Next.js **route groups** (`app/(app)/...`) and **dynamic
segments** (`app/[id]/...`, `app/api/[...path]/...`). Mermaid reserves those characters for node
shape syntax, so an id like `app_(app)_page_tsx` or `app_..._[id]_..._tsx` made the entire
flowchart fail to parse — the HTML viewer showed an empty pane with "Syntax error in text", and
the interactive click-to-focus broke with it.

Root cause: `nodeId()` in both `src/render/mermaid.ts` and `src/render/dot.ts` only replaced `/`
and `.` with `_`, leaving parens/brackets in the emitted ids.

- Both `nodeId()` copies now collapse **every** character outside `[A-Za-z0-9_]` to `_`. This
  fixes Mermaid parsing and, because the resulting id is pure word characters, keeps it verbatim
  in Mermaid's rendered SVG element ids — which `src/render/html.ts` parses back out for
  click-to-focus, so that feature keeps working on the previously-broken nodes.
- **Labels are untouched**: the quoted `["app/(app)/teacher/[id]/page.tsx"]` still shows the real
  path to the reader (parens/brackets inside a quoted Mermaid label are valid — verified).
- This is a rendering-only change. `check`/`--json` output, diagnostics, and resolution are
  unaffected; the `--json` contract is unchanged.
