## Changes

The npm registry already has an unrelated package named `spokes` (a pub/sub event library,
unaffiliated with this project) — discovered via `npm view spokes` when checking publish
readiness. Since this project has never been published, renamed before that could become a
problem:

- npm package name: `spokes` → `spokes-ai-humanism` (confirmed available via registry lookup).
- The CLI command itself stays `spokes` (e.g. `npx spokes check`) — the `bin` field's key is
  independent of the package `name` field, and changing it would have meant rewriting every
  example in the README for no functional benefit.
- `spokes init`'s written `spokes.config.json` now points `$schema` at
  `./node_modules/spokes-ai-humanism/schema.json` instead of the old (now-incorrect)
  `./node_modules/spokes/schema.json` — verified by running `spokes init` fresh and inspecting
  the output.
- `package-lock.json` regenerated to match (also picked up a stale `1.0.0` version field that
  had drifted since v1.0.0 and was never refreshed by the intervening patches).
- README install instructions updated, with a note that `npx spokes ...` requires the
  `npm install` step first (it resolves to the local `node_modules/.bin/spokes`; a zero-install
  `npx spokes` would hit the *other*, unrelated npm package).

This patch does not publish the package — that remains a separate, explicit action not taken in
this session. All 32 existing tests still pass unchanged.
